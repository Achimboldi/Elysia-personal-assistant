### 4. 修复：删除提醒后云同步复活问题（电脑端）
- 现象：用户在电脑端/手机端删除提醒任务后，提醒会在云同步后恢复出现。
- 根因（双端一致）：
  1. 删除提醒不写墓碑：`reminder-manager.js deleteReminder` 只从 settings.reminders splice，未记录 deletedItems.reminders
  2. 提醒合并无墓碑过滤：`mergeReminderLists`（main.js）/ `_mergeReminders`（手机端 agent_sync_helper）都是"云端独有保留"；云端残留的已删除提醒被当独有合并回本地 → 复活
  3. reminders 不在墓碑集合（_tombstoneCollections / applyDeletionTombstones collections）中
- 修复（电脑端，手机端按用户要求暂缓）：
  - `reminder-manager.js`：persistReminders 支持 deletedItemsOverride 参数；deleteReminder 删除时写墓碑 deletedItems.reminders
  - `main.js`：新增 filterRemindersByTombstone 辅助函数；applyDeletionTombstones 增加 reminders 墓碑过滤（过滤 mergedData.settings.reminders + combined.reminders 回传）；手动云下载路径 mergedSettings 后应用 filterRemindersByTombstone
- 覆盖路径：自动同步主 merge（_mergeWithConflictDetection→applyDeletionTombstones）、自动同步下载（_downloadCloudData→applyDeletionTombstones）、手动云下载（mergedSettings 单独过滤）
- 验证：node --check 双端通过；逻辑测试（墓碑过滤场景）通过；win-unpacked 与 linux-app 两目录文件已同步一致
- 遗留：历史已删除但云端仍残留的提醒，修复后首次同步仍可能复活一次（当时无墓碑），需再手动删除一次即可写入墓碑

### 5. 修复：提醒时间修改后，另一台电脑同步下载又变回旧时间
- 现象：A 电脑修改提醒时间 → 同步云端 → B 电脑下载 → B 上提醒时间又变回旧值。
- 根因：`reminder-manager.js updateAfterFire`（触发提醒后更新状态）会执行 `r.updatedAt = nowIso`——**提醒触发（自动/手动）把 updatedAt 提升到触发时刻**。实测 data.json 中 4/5 条提醒的 updatedAt 都等于 lastTriggeredAt（触发时间）。多机同步时：B 机若触发过该提醒，本地 updatedAt 变新（但 schedule 仍是旧值），上传后在 `mergeReminderLists`（按 updatedAt 取胜者）中**旧 schedule 版本假胜出**，覆盖 A 机的真实修改 → 时间"变回去"。
- 修复：`updateAfterFire` 移除 `r.updatedAt = nowIso`——触发只更新触发状态（lastTriggeredAt/triggerCount/history/nextTriggerAt），不再污染内容级时间戳。这样合并时 updatedAt 只反映用户真实修改。
- 验证：
  - node --check 双端通过，两端文件一致
  - 模拟验证：修复前 B 机旧 schedule(15:00) 假胜出（bug 复现）；修复后用户修改(16:00) 正确保留
  - 真实 data.json 端到端合并测试：用户修改（23:00）胜出，不被触发时间戳覆盖
- 说明：已有被污染的历史数据无需清理（用户下次真实修改时 updatedAt 自然更新为新值，合并即正确）
